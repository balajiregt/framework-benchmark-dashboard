THE BENCHMARK SYSTEM

From a claim to evidence you can inspect

Three different questions, one shared publishing pipeline.

Open / save diagram ↗
01 / FREEZE

Same task, two conditions

Hold requirements, app, model settings and runner constant. Add existing helpers and conventions only to the framework condition. Alternate which arm goes first.

02 / CHALLENGE

Passing is only the beginning

Run each generated test unchanged against the healthy app and isolated faults. A fault must be activated and cause an assertion failure to count as detected.

03 / ACCOUNT

Measure what happened

Record completion, check coverage, wall time and provider tokens. Show estimated cost separately. Human correction time stays unavailable until a person reviews and corrects a submission.

04 / PUBLISH

One automatic evidence trail

Keep prompts, code and logs private. Publish only reviewed schema fields and hashes to repository result branches. The dashboard refreshes those feeds every minute.

Evidence boundary

These are controlled synthetic application benchmarks. Passing checks does not establish production reliability, financial savings or AI productivity. Missing measurements remain unavailable. This site automatically reads published repository results; it does not execute tests or call model providers.
