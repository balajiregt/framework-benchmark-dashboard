01 / FREEZE

Same task, two conditions

Hold requirements, app, model settings and runner constant. In workflow trials, both conditions have the same helpers; only the context layer differs. The earlier generation pilot bundled helpers in one prompt. Alternate which arm goes first.

02 / CHALLENGE

Passing is only the beginning

For create/update tasks, check the frozen tests against healthy behavior and isolated faults. For scenario validation, review the conclusion against source and contract evidence. A healthy test pass alone is insufficient.

03 / ACCOUNT

Measure what happened

Record completion, check coverage, wall time and provider tokens. A timing audit separates valid attempts from host interruptions. Show estimated cost separately. Human correction time stays unavailable until a person reviews and corrects a submission.

04 / PUBLISH

One automatic evidence trail

Keep prompts, code and logs private. Publish only reviewed schema fields and hashes to repository result branches. The dashboard refreshes those feeds every minute.

Evidence boundary

These are controlled synthetic application benchmarks. Passing checks does not establish production reliability, financial savings or AI productivity. Missing measurements remain unavailable. This site automatically reads published repository results; it does not execute tests or call model providers.
